## Tester feedback list (done)

## Bugs found

- Stats tooltip in StatsPane sometimes remains on screen after closing the StatsPane
- ItemBagPane shows an icon of th a coin all the time, even when you are not getting coins. If not coins are gained on that level, this icon should hide

## Quality of life and game feel improvement
- When pressing shift to see which items are granting you the hovered stat, reduce the visibility even more of those items that do not grant you the stat. It should be more noticeable
- ItemBagPane, item tooltip stay on window all the time, it is not consistent with the rest of the tooltips
- When pressing escape during the ItemBag window, it pauses the game it causes the game to misbehave. We shoulda bout pause while this screen is shown and when the SelectUpgradePane too
- Check cooldown for special attacks, specially the warrior class, it does not seem to be affected by attack speed stat or the cooldown time that the tooltip advertises is not matching the actual cooldown
- Most testers don't like the transparency on the boss while it is invulnerable during the first phase. Remove that transparency, we will find another way to show the player it is invulnerable, probably the art team will modify the stats
- When damaging an invulnerable enemy, change the damage numbers vfx from 0 to IMMUNE
- Change whirlwind ability slightly. Instead of damaging enemies once it should inflict damage over time. We are planning to introduce a longer animation for this skill, so it will probably work better like that. At base it should cause 20 damage every 0.5 seconds, the new animation will last 2 seconds. Upgrades of this ability should increase damage and reduce the interval to 0.4, 0.3 and 0.25. Numbers will be adjusted for balance
- The shield spawned by the whirlwind ability needs to last longer, at least 3s 
- Improve the Lock-on system.
  - For mouse and keyboard, besides the current behavior, you should be able to click on enemies to lock-them
  - For both, mouse and keyboard and gamepad, when pressing again the lock-on key instead of de-selecting the current target, it should cycle between nearby enemies, considering the range
- Add favors to the Inventory window and to the LevelSelectionScene, in both cases next to the current gold
- Add an area of effect for melee enemies, so the player can clearly see the the melee damage is going to fall. In order for this to work, we should probably reduce the animation speed a bit. There is an asset package that can help with this, let's explore if it is convinient to use it or if it is better to do it from scratch

## Systems Improvements
- RunEncounter events improvements
  - RunEncounters are done to add exposition to the player of the lore and worldbuilding
  - Testers say adding the possible outcomes to the options of the events reduce the exposition because player will not read the lore or the options, only the possible outcomes
  - Suggestion is to change the outcomes tooltip for something more vague. Example instead of saying "May reduce health 10-20 and grant an item of X quality" we should say "The group you encounter may be offended by this action, so a fight could erupt, but it seems they have many riches on them..."
  - Add descriptions to the results. Currently only the results are shown like this "You gained 10 health, you lost 5 grace" We need to add what actually happened. Following the example from above "These people attacked you, but they were no match so you only lost 4 health, and you found on their loot the item <item name>"
  - Add other stats as modifiers for the outcomes, not only luck. Most of them will still have luck as the modifier, but for example for a potential fight attack and armor could affect the outcome too. For an option that allows you to flee, MoveSpeed can be considered
  - Evaluate the idea to add a tree of multiple events to a single run encounters. Example, for the event that the player find a faraclarian clan of warriors, if the player answers "Yes I saw the person you are asking about" then the warriors asked "Oh then describe it" and the event gives you two options, one correct and another one incorrect.
  - ALSO since we recently recided that each playable character will be a different character, we should consider give different options for each class.

### Lock-on: click to lock, tap cycles, tap away to release (2026-10-26)
Toggle mode (default): a tap of F / LT locks the nearest enemy; tapping again moves the lock to the next enemy in lock range, clockwise around the player; once no enemy is in range (you walked away), a tap releases it. With only the locked enemy in range, a tap does nothing. With the mouse, left-clicking an enemy locks it and attacks it.
- [x] Next to a group: tap F, the nearest gets the marker. Tap again a few times: the marker goes around the group clockwise and comes back to the first.
- [x] Gamepad: same with LT.
- [x] Walk away until no enemy is within reach, tap: the marker disappears. Near only the locked enemy, tap: the lock stays.
- [x] Mouse: left-click an enemy (also a small slime, and the boss's body): it's locked and attacked. Click empty ground: you attack there and the lock doesn't change. Click a far enemy: it's locked even out of range (the attack fires once it's in range).
- [x] Hold mode (Settings): hold F/LT to lock as before; while holding, clicking another enemy moves the lock to it; release unlocks.
- [x] The locked enemy dies: the lock ends as before (Toggle mode).
- [x] Archer barrage / Augur explosions still go to the locked target.

### Whirlwind rework: 2 s spin with damage ticks, no invulnerability (2026-10-26)
The Whirlwind now keeps hitting for 2 s: each enemy on contact, then every 0.5 / 0.4 / 0.3 / 0.25 s (tier 0 / +1 / +2 / +3) while it stays in the spin. The current spin animation (0.58 s) replays until the 2 s are up; the 2 s animation will just play once. The Warrior can be hurt while spinning now. The holy shield (tiers +1..+3) lasts 3 / 3.5 / 4 s. New columns in Ability_Whirlwind: Spin Duration and Tick Interval; the Glyph text no longer says "You can't be hurt while spinning".

- [x] Warrior, tier 0: the spin lasts about 2 s (the animation loops with no idle frame in between, or say if it flickers). An enemy standing in it takes a hit about every 0.5 s (4-5 damage numbers); one that walks in later is hit at once.
- [x] Enemy hits land on the Warrior during the spin (no invulnerability).
- [x] Dash during the spin: the dash happens at once and the spin stops (no more hits, the spin animation doesn't come back).
- [x] Tier +1..+3 (cheat window: swap the Glyph tier): faster ticks; the shield VFX lasts 3 / 3.5 / 4 s and absorbs projectiles.
- [x] Glyph tooltip: "Base damage 20 every 0.5s for 2s" (tier 0), and the shield line on upgraded tiers.
- [x] The basic swing is unchanged (one hit per enemy per swing).
- [x] Balance feel: the special now deals several times its old damage to a crowd; note numbers for the balance pass.
